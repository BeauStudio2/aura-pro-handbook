Project and asset model

Represent what exists, where it is, what depends on it, and what is known as of a date.

Inputs and outputs

Inputs
Drawings and revisions, asset identities, observations, installed work, resources, and commitments.
Expected output
A dated view of the undertaking in which a local change can be traced to affected decisions.

Across the architecture

Approach

Represent each building, floor, bay, system, and asset with a durable Aura Pro identity. Attach the design state, reported installed state, and verified state as dated claims. Track how spaces and objects relate to decisions, work packages, and other systems.

Store quantities as measurements of an element with a stated basis. For one slab, the drawing gives a design volume, delivery tickets give the volume supplied, and the field record gives the accepted installed volume. Link each to its source and revision. An estimate line records which measurement and rate produced it. How quantities support an estimate

How it works

An architect issues a revision for the bay. Map its model element or drawing location to the physical bay, compare it with the prior revision, then list dependent lift plans and inspections. A later field measurement updates the installed condition while keeping the original design available. A changed external element ID triggers a match review where identity is uncertain.

Technology choices

Use PostgreSQL for identity, revisions, and typed relationships. Add spatial queries when needed; large files stay in object storage. Link the issued drawing revision in Procore to the physical location and any model geometry the team supplies. A dated field observation can then update the installed condition.

Integration and native ownership

Aura Pro owns the physical identity and change history from the beginning. Specialist tools can continue authoring geometry. Native mappings and a model viewer can progressively replace manual cross-reference work. Test a renamed object, a moved object, and a deleted-and-recreated object across revisions before automatically transferring dependencies.
